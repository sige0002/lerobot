# Issue Log

再利用できる問題と対処を1問題1エントリで記録する。通常の成功した作業すべてを記録対象にしない。
このリポジトリの保存先は `issue/issue_N.md`（現在のファイルは `issue/issue_1.md`）。既存の保存先・公開範囲を尊重し、別のログ体系を勝手に作らない。

## 検索と更新

- 具体的なエラー・機能名で `rg` を使い、見出しや `area:` / `kind:` から候補を絞る。候補の本文を読み、同じ問題ならそのエントリを更新する。
- 原因、効いた対処、必要なら再現・検証コマンドを簡潔に残す。固有名やエラーメッセージはタイトル・本文に入れる。
- 未解決なら暫定対処と残った問題を明示する。新規エントリは末尾へ追記し、日付とドキュメント言語を既存形式に合わせる。

## 既存形式

```markdown
## 問題の具体的なタイトル (YYYY-MM-DD)

**問題**: 現象と原因。

**解決**: 有効だった対処と必要な検証。

area: 既存のarea一覧から選ぶ
kind: bug
```

`kind` は `bug / perf / build / config / test / git / experiment / docs` から1つ。
`area` はファイル冒頭の一覧から1つ以上選ぶ。追加が必要なら先に一覧を更新し、
`infra`（依存・環境）と `repo`（git・文書）も使い分ける。固有名ごとにタグを増やさない。

ログはローカル知識として扱い、既存のignore状態を確認する。分割が必要になったら連番を進め、
見出しとarea一覧を次ファイルへ引き継ぐ。既存の目安は200行。単なる行数の超過で空ファイルを先に作らない。
